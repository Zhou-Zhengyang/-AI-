# 风险判定与确认

## 何时用这个技能

决定一个操作能不能直接执行、要不要用户确认、还是直接拒绝。

也包括：令牌怎么签发、怎么校验、过期怎么处理。

## 三色含义

| 颜色 | 含义 | 界面表现 |
|---|---|---|
| 绿 | 只读或可逆低风险，直接执行 | 显示结果 |
| 黄 | 有资金或状态变化，需确认 | 弹确认卡片 |
| 红 | 不可逆或越权，直接拦截 | 显示拦截理由 |

判定顺序：先查基础等级，再叠加四个维度，取最高等级。任一维度判红即红。

## 四个维度

| 维度 | 规则 | 后果 |
|---|---|---|
| 操作类型 | 只读绿、动账黄、改规则红 | 决定基线 |
| 金额 | 单笔超一千元拦、日累计超五千元拦 | 判红 |
| 收款人 | 首次且超五百元 | 判红 |
| 可逆性 | 挂失、改额度、改密码、申购赎回 | 判红 |
| 频次 | 当日同工具超五笔 | 判红 |

阈值写在配置里，不要散落在代码里。

## 判定输出

必须带三样，缺一不可。

```ts
{
  level: "yellow",
  blocked: false,
  requiresConfirm: true,
  hits: [
    { rule: "base-level", detail: "转账基础等级为 yellow" },
    { rule: "new-payee", detail: "首次收款人且金额 500 元" }
  ],
  summary: "需确认：向首次收款人转账 500 元"
}
```

只说「需确认」不说是哪条规则的判定，评审时会被追问到答不上来。

## 确认令牌

令牌绑定四样东西，少一样都能被利用。

| 绑定项 | 防什么 |
|---|---|
| 会话标识 | 防跨会话盗用 |
| 工具名 | 防确认转账却执行挂失 |
| 参数摘要 | 防确认后改金额 |
| 过期时间 | 防长期有效 |

校验流程固定三步：查存在、查未过期、重算参数摘要比对。

三步全过才执行。任何一步失败，返回明确原因，不执行。

令牌一次性。执行后立即失效，重复提交返回「令牌已使用」。

## 拦截话术

不要说「操作被拒绝」，要说清楚三件事：拦了什么、为什么拦、还能怎么办。

示例：「这个操作我不能直接执行。金额 5000 元超过单笔限额 1000 元。可以拆成多笔，或到柜面办理。」

不可逆操作要给出替代路径，不要让用户卡住。

## 验收

四种输入各有结论：只读绿、小额动账黄、超限红、不可逆红。

令牌四类攻击各一条：篡改参数、换会话、重放、过期。

拦截话术里能看到具体金额与具体限额。

## 反模式

判定只返回布尔值。没有规则名的判定无法解释，也无法测试。

把阈值写死在判定函数里。改一次要全文搜索。

令牌用自增序号或时间戳。可预测的令牌等于没有令牌。

确认后再校验一次参数，但用客户端传回的值。要用服务端存的原始参数重算摘要。
