# 银行意图解析

## 何时用这个技能

用户说了一句中文，系统要决定「这是哪个业务、要填哪些参数」。

也包括：规则命中不了、模型输出不合法、多轮缺参数要追问。

## 六个场景与代表说法

| 场景 | 代表说法 | 落到的工具 |
|---|---|---|
| 转账 | 转给小王五百、定时下周给房东转房租、AA 一下三个人 | `transfer`、`schedule_transfer`、`create_aa` |
| 账单 | 这个月钱花哪了、有没有异常交易、去年一共花多少 | `analyze_bills` |
| 理财 | 有什么稳健产品、我的风险等级、赎回稳盈货币 | `wealth_list`、`wealth_risk`、`wealth_redeem` |
| 卡片 | 卡丢了、锁一下、额度调到两万、申请新卡 | `list_cards`、`report_loss`、`lock_card`、`adjust_limit`、`apply_card` |
| 订阅 | 我订了哪些、什么时候扣费、把视频会员退掉 | `list_subscriptions`、`subscription_reminder`、`cancel_subscription` |
| 生日 | 帮我准备生日、锁定一千、订个蛋糕 | `birthday_lock`、`birthday_book` |

## 解析顺序

固定四步，不许跳。

**一、匹配场景。** 按关键词表匹配，越具体的规则越靠前。「取消视频会员」先匹配订阅，不匹配卡片。

**二、抽槽位。** 只抽契约里声明的字段。金额先抹掉手机号与长数字，再识别中文数字与万、千。

**三、判缺失。** 必填槽位缺失就进追问，不调用执行。

**四、给置信度。** 明确命中给高值，模糊命中给低值，判不出给零。

## 常见歧义处理

| 说法 | 处理 |
|---|---|
| 转给 13800138000 五百 | 手机号先映射成通讯录姓名，再当收款人 |
| 五千块 | 金额 500000 分，不是 5000 |
| 三千五 | 3500 元，不是 3050 |
| 把理财都取出来 | 赎回，金额缺省为全部 |
| 卡丢了 | 挂失，判红，不可撤销 |
| 按备注转给张三 | 直接拒绝，收款人来源不可信 |

## 追问的话术

不要问「你要多少钱」，要问「还需要确认：金额是多少」。

一次只问缺的项。缺两项时合成一句：「还需要确认：收款人和金额。」

追问后把已抽到的槽位存成草稿，下一轮只补缺的部分。

## 规则与模型的分工

规则先跑。规则判不出或置信度低于阈值时，才交给模型。

模型输出必须过契约校验：工具在白名单、参数类型正确、数值在范围内。任何一条不过，丢弃该字段而不是整条接受。

模型失败、超时、返回乱码，一律降级回规则，不阻塞对话。

## 验收

六类说法各一条能正确路由。

金额覆盖：阿拉伯数字、中文数字、万、千、带小数。

歧义表六条全部按预期处理。

## 反模式

把工具清单写进提示词的自然语言描述里，会撑大每次请求。工具声明应该走结构化字段。

让模型直接产出可执行动作。模型只给意图，执行权在代码层。

用正则匹配整句。中文说法太活，按关键词分段匹配更稳。
