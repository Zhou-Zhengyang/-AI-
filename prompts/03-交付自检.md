# 提示词三：交付自检

提交前把这段给 AI 助手，让它按清单核对，不要自己判断「差不多可以了」。

---

```
背景：我的银行智能体项目准备提交 2026 FinTechathon。请你按下面的清单逐条核对，只读不改，发现问题列出来我自己决定改不改。

核对项分五组。

第一组，能不能启动。
- `node scripts/check.mjs` 是否通过
- `node scripts/smoke.mjs` 是否通过
- 前端 `npm run build` 是否通过
- 启动后浏览器能不能打开，控制台有没有报错

第二组，能不能演示。
- 六个场景里做了几个，分别是什么
- 演示路径是否依赖网络
- 演示数据能不能一键重置
- 有没有三分钟以内的录屏

第三组，能不能证明。
- 三色判定在界面上是否可见
- 命中的规则名是否可见
- 审计序号与链校验是否可见
- 拦截用例能不能现场复现，至少五条

第四组，安全。
- 按 `review/security-review.md` 七项，逐项给结论
- 仓库里搜一遍密钥特征
- 日志与错误信息里搜一遍明文卡号与手机号

第五组，仓库卫生。
- `git status` 是否干净
- 有没有提交 `node_modules`、`dist`、`.env`
- `CHANGELOG.md` 是否记录了完整演进
- 分支是否与远端一致

输出格式：

```
一 能启动：通过 / 不通过（不通过写原因）
二 能演示：做了 x/6 个场景，具体是 xxx
三 能证明：通过 / 不通过
四 安全：七项里通过 x 项，不通过的是 xxx
五 仓库：通过 / 不通过

阻断项（必须修）：
- 文件:行 问题

建议项（可排期）：
- ...
```

约束：
- 不要替我改代码，只给结论。
- 不要写「基本通过」，只有通过与不通过两种结论。
- 找不到证据的项记为不通过，不要脑补。
- 结论出来后，告诉我最少要修哪几项才能提交。
```

---

## 核对之后

按阻断项一条一条修，每修一条重跑一次 `check.mjs`。

修完重新跑这段提示词，直到五组全过。

最后打标签。

```powershell
git tag v1.0.0
git push origin main --tags
```
