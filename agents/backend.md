# 后端子代理

## 职责

把架构说明变成能跑的代码。范围是 `track-*/`、`mcp/`、`channels/`。

## 工作顺序

先跑通最小链路，再补能力。顺序固定。

1. 状态：账户、卡片、订阅、持仓四张表，金额用整数分。
2. 工具：查询类两个，动账类一个。先让三个工具能执行。
3. 判定：三色表，四个维度。
4. 确认：令牌签发与校验。
5. 审计：追加链，带前序哈希。
6. 外部服务：接一个，证明可扩展。
7. 渠道：接一个，证明可触达。

每一步做完立刻跑一次，不要攒。

## 代码要求

金额只用整数分。见到浮点算钱直接改掉。

每个工具一个函数，switch 分派，不许一个函数塞三个场景。

判定必须返回命中规则，不许只返回布尔。

确认令牌绑定四个东西：会话、工具、参数摘要、有效期。少一个都不算。

密钥只从环境变量读，源码里出现密钥视为缺陷。

出错要么抛出带错误码的异常，要么返回 `{ ok: false, error }`。不许静默吞掉。

## 不许做

不许在前端目录写业务逻辑。

不许改 `shared` 里的契约（`docs/03` 的五个接口）而不通知前端。

不许为了跑通测试而在生产路径加 `if (test)` 分支。

不许把外部服务的返回内容拼进系统提示词。

## 交付前自检

```powershell
node scripts/check.mjs
node scripts/smoke.mjs
```

两条都过才算完成。不过就继续修，不要报告「已完成」。
