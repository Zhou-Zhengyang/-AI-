# 界面评审清单

界面是评委唯一直观看到的部分。这份清单只关心「能不能看懂」。

## 三种颜色

- 绿、黄、红三种判定颜色在界面上能区分。
- 颜色含义与判定一致，没有反着用。
- 色盲友好：颜色之外还有文字标记。
- 红色判定不出现确认按钮。

## 一屏能看完

- 打开页面不需要滚动就能看到对话区、状态区、审计区。
- 输入框始终可见。
- 消息不超过三行不换行溢出。
- 长数字不挤破布局。

## 数字来源

- 余额与接口返回一致。
- 审计序号与后台一致。
- 金额展示两位小数，带单位。
- 没有前端自己算出来的业务数字。

## 交互

- 回车发送，Shift 加回车换行。
- 发送后输入框清空。
- 请求进行中有可见的等待状态。
- 确认卡片点完即消失，不重复出现。

## 文案

- 没有内部字段名（如 `amountCents`、`policyLevel`）。
- 没有 `undefined`、`null`、`[object Object]`。
- 没有英文报错直接抛给用户。
- 拦截提示说清「为什么」与「怎么办」。

## 审计展示

- 显示最近十条。
- 每条显示序号、时间、判定、结果。
- 链校验状态可见。
- 能看出记录被篡改时的差异。

## 截图可用性

- 1366 宽度下布局不变形。
- 深色背景与浅色背景都清晰（如支持）。
- 截图能直接放进 PPT，不需要裁切。

## 结论

```
阻断项：__ 条（信息泄漏、颜色错乱、数字不符）
严重项：__ 条（交互不顺、文案不清）
一般项：__ 条（间距、字号）
结论：可演示 / 不可演示
```
