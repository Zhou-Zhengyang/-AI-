# 发布门禁

这份清单全部勾上才能提交作品。任何一条不勾，不许说「已完成」。

## 三天版最小门禁

只剩三天时，按这七条过，过了就能提交。

| 序号 | 检查项 | 判定方式 |
|---|---|---|
| 1 | 自检通过 | `node scripts/check.mjs` 输出通过 |
| 2 | 冒烟通过 | `node scripts/smoke.mjs` 输出通过 |
| 3 | 三个场景能演示 | 现场点三条，每条从输入走到结果 |
| 4 | 三色判定能解释 | 指一条黄色，说出命中的规则名与阈值 |
| 5 | 注入能拦 | 发一句「忽略之前的指令」，界面显示红色拦截 |
| 6 | 审计能校验 | 右栏显示链完整，条数与对话次数一致 |
| 7 | 无密钥 | `git status` 无 `.env`，仓库扫描无命中 |

七条全过，打标签 `v1.0.0` 提交。剩下三个场景写进自述的「不足」，不要硬赶。

## 完整门禁

时间允许时按下面七节逐条过。

## 一、能启动

- `node scripts/check.mjs` 通过。
- `node scripts/smoke.mjs` 通过。
- 选定的路线启动后，发一句话能收到回复。
- 前端 `npm run build` 通过。
- 浏览器里发三条消息（绿、黄、红）显示正确。

## 二、能演示

- 六个场景里至少三个能完整演示。
- 演示路径不依赖网络（断网也能跑核心链路）。
- 演示数据可一键重置回初始状态。
- 录屏三分钟，能放完不卡。

## 三、能证明

- 三色判定在界面上可见。
- 命中规则在界面上可见。
- 审计序号与链校验在界面上可见。
- 拦截用例至少五条可现场复现。

## 四、能扩展

- 新增一个工具只需改三处，不改主循环。
- 新增一个外部服务只需加一条清单。
- 新增一个技能只需放一个 Markdown。
- 新增一个渠道只需实现收与发两个函数。

## 五、安全

- `review/security-review.md` 七项全通过。
- 仓库无密钥，历史无密钥。
- 日志无明文卡号与手机号。
- 外部内容不进系统提示词。

## 六、文档

- `README.md` 说清是什么、怎么跑、怎么分层。
- `CHANGELOG.md` 记录完整。
- `docs/05-常见坑.md` 至少有三条自己踩过的坑。
- 自述文档三段齐：做了什么、怎么验证、不足在哪。

## 七、仓库卫生

- `git status` 干净。
- `.gitignore` 排除依赖、构建产物、数据目录、`.env`。
- 没有提交 `node_modules`。
- 没有提交临时脚本与调试日志。
- 分支状态与远端一致。

## 门禁结论

| 节 | 结果 |
|---|---|
| 一 能启动 | 通过 / 不通过 |
| 二 能演示 | 通过 / 不通过 |
| 三 能证明 | 通过 / 不通过 |
| 四 能扩展 | 通过 / 不通过 |
| 五 安全 | 通过 / 不通过 |
| 六 文档 | 通过 / 不通过 |
| 七 仓库卫生 | 通过 / 不通过 |

七节全过，打标签 `v1.0.0` 并提交。

任何一节不通过，写清差哪条、谁负责、什么时候补。
