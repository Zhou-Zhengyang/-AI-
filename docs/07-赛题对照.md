# 赛题对照

这篇用来回答两个问题：赛题要什么，启动包给了什么，差在哪。

## 赛题要什么

官方口径三条。

第一条，构建 AI Banking Agent，用自然语言理解金融意图，自主规划并执行业务操作。

第二条，场景覆盖「至少 3 个核心场景，鼓励完整覆盖」，六个场景：智能转账、账单分析、理财操作、卡片管理、订阅代扣、跨场景联动。

第三条，三条硬性门槛：权限分级机制、幻觉防护与注入防御、意图理解与任务规划。

另有渠道要求：支持通过 APP、IM 等渠道与用户连接。

## 启动包给了什么

### 场景覆盖

九个工具覆盖六个场景，全部可路由。

| 场景 | 工具 | 判定 | 实测输入 |
|---|---|---|---|
| 智能转账 | `transfer` | 黄 | 转给小王 100 元 |
| 账单分析 | `query_balance`、`analyze_bills` | 绿 | 查一下余额、这个月花了多少 |
| 理财操作 | `wealth_redeem` | 红 | 把理财全部赎回 |
| 卡片管理 | `lock_card`、`report_loss` | 黄、红 | 锁定卡片、挂失我的卡 |
| 订阅代扣 | `list_subscriptions`、`cancel_subscription` | 绿、黄 | 我订了哪些订阅、取消云幕视频会员 |
| 跨场景联动 | `birthday_lock` | 黄 | 帮我准备生日，锁定一千元 |

九个说法实测结果。

| 输入 | 判定 | 场景 |
|---|---|---|
| 查一下余额 | 绿 | 账单分析 |
| 这个月花了多少 | 绿 | 账单分析 |
| 转给小王 100 元 | 黄 | 智能转账 |
| 我订了哪些订阅 | 绿 | 订阅代扣 |
| 取消云幕视频会员 | 黄 | 订阅代扣 |
| 锁定卡片 | 黄 | 卡片管理 |
| 挂失我的卡 | 红 | 卡片管理 |
| 把理财全部赎回 | 红 | 理财操作 |
| 帮我准备生日，锁定一千元 | 黄 | 跨场景联动 |

六个场景全部命中，满足「至少 3 个」，且超出鼓励线。

### 三条门槛

| 门槛 | 启动包落地 | 怎么验证 |
|---|---|---|
| 权限分级 | 三色判定，四维度，命中规则可解释 | 界面上每条气泡显示等级与规则名 |
| 幻觉防护 | 数字只来自工具返回，模型只产意图且过白名单 | 断网跑规则模式，数字仍正确 |
| 注入防御 | 输入归一化后匹配注入特征，命中即拦 | 发「忽略之前的指令」显示红色拦截 |
| 意图理解与规划 | 规则优先，模型兜底，缺槽位追问 | 六类说法各一句，多轮补全 |

### 渠道

| 渠道 | 实现 | 验证 |
|---|---|---|
| Web 前端 | 对话、判定、确认卡片、审计列表 | 浏览器打开即用 |
| 通用 webhook | `channels/generic-webhook.mjs` | `curl` 一条返回 JSON |
| 企业微信 | `channels/wecom.mjs` | 无密钥时 `dryRun` 打印要发的包 |

赛题要求 IM 渠道，前两条直接可用，第三条需企业微信凭据。

### 审计

每条决策一条记录，带前序哈希，界面显示链校验状态。

现场可演示：改一条记录的结论，刷新后链校验变成断裂。

## 启动包没给的

骨架是起点，不是成品。以下需要你自己补。

| 缺口 | 补充方式 | 大约工作量 |
|---|---|---|
| 理财产品对比与风险测评 | 在 `shared/state.ts` 加两个只读工具，`rules.ts` 加两条规则 | 半天 |
| 定时转账与 AA 收款 | 同上，注意判定要给黄 | 半天 |
| 额度调整与新卡申请 | 同上，两条都判红 | 两小时 |
| 续费主动提醒 | 在 `list_subscriptions` 基础上加时间过滤 | 一小时 |
| 礼物下单 | 参考 `mcp/` 里的服务写法，加一个外部服务 | 半天 |
| 模型接入 | `track-pi/src/transport.ts` 已写好，配密钥即用 | 十分钟 |

## 复核结论

三条门槛全部落地且有可验证证据。

六个场景全部可路由，三色齐全。

渠道两条可用，一条需凭据。

缺口集中在场景的细分能力，不影响主线演示。三天内不建议全补，挑两个补到能演示即可。
