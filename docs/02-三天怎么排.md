# 三天怎么排

只剩三天时，排期要按「可演示」倒推，不按「功能多」正推。

## 总表

| 天 | 主线 | 当天必须拿出的东西 |
|---|---|---|
| 1 | 骨架与判定 | 六类说法能路由，判定能解释原因，界面能对话 |
| 2 | 场景与扩展 | 三个场景端到端可演示，一个外部服务与一个渠道可用 |
| 3 | 证据与交付 | 安全清单全过，三分钟视频，自述文档，仓库干净 |

## 第一天：骨架与判定

上午两小时：选路线、装环境、跑通 `check.mjs` 与 `smoke.mjs`。跑不通就先解决环境，不要带着问题往下走。

下午四小时：意图解析补到六类，三色判定补到四维度，前端显示命中规则。

晚上两小时：写六条测试用例，跑一遍冒烟。

当天不做的事：不接模型，不接外部服务，不做新场景。判定没讲清楚之前，这些都不许开。

验收：一句「转给小王 500 元」在界面上能看到具体拦截原因，不是只显示红色。

## 第二天：场景与扩展

上午三小时：挑三个场景做到端到端。推荐查余额、账单分析、取消订阅，这三条链路短、演示稳。

下午三小时：接一个外部服务（汇率最简单），接一个渠道（通用 webhook 最快）。

晚上两小时：把三个场景各录一段十秒视频，确认演示路径不依赖网络。

当天不做的事：不加第四个场景，不美化界面，不接模型。

验收：`curl` 一条渠道请求能拿到带判定颜色的 JSON 回复。

## 第三天：证据与交付

上午三小时：按 `review/security-review.md` 逐条过，不通过的立刻修。

中午一小时：录三分钟演示视频，顺序固定：正常办理 → 越权拦截 → 注入拦截 → 外部服务与渠道。

下午两小时：写自述文档，三段结构，第三段写具体能力缺口。

傍晚一小时：`git status` 确认干净，打标签 `v1.0.0`，提交。

当天不做的事：不加功能，不改架构，不重构。只修文案与明显缺陷。

验收：`review/release-gate.md` 七节全勾。

## 每天固定的四个动作

开工前跑一次 `node scripts/check.mjs`。

开工前把当天的提示词从 `prompts/02-三天冲刺.md` 复制给 AI。

收工前跑一次 `node scripts/smoke.mjs`。

收工前在 `CHANGELOG.md` 记一行，写清当天做了什么、还剩什么。

## 三天里的取舍顺序

时间不够就按这个顺序砍，砍到能交付为止。

| 顺序 | 砍掉 | 影响 |
|---|---|---|
| 1 | 第二个渠道 | 不影响主线，答辩少一个亮点 |
| 2 | 外部服务 | 少一个扩展证据，场景仍在 |
| 3 | 第四个到第六个场景 | 赛题允许只做三个 |
| 4 | 界面美化 | 功能仍在，观感下降 |

永远不砍：三色判定、注入防御、审计留痕。这三样是评分主线，砍了等于弃赛。

## 每天卡住时

先看 `docs/05-常见坑.md`，里面按「症状 → 原因 → 处理」组织。

一条都匹配不上，就在那里加一条新的，写清现象与解法。三天结束后，这份文件就是你的经验沉淀。

实在解决不了，走降级路径：把这条能力写进自述的「不足」，把时间投到能演示的三条链路上。

## 第三天的红线

上午十点还没开始录视频，立刻停止所有开发。

下午三点还没写自述，立刻停止改代码，先写文档。

提交前两小时不再改任何代码，只跑清单。
