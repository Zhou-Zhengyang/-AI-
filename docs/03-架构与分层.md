# 架构与分层

两条路线共用同一套分层，差异只在第四层怎么装配。

## 五层结构

```
第一层  入口      前端页面 / IM 渠道
第二层  协议      HTTP 或 webhook，统一成内部请求
第三层  编排      意图解析 → 判定 → 确认 → 执行 → 审计
第四层  装配      Cordis 插件 或 pi 三段式
第五层  能力      工具、外部服务、技能、状态
```

分层规矩：只能上层调下层，不许下层反向调上层。第五层不知道有 HTTP，第三层不知道插件怎么写。

## 请求怎么走

一次对话走完六段，每段都可单测。

```
用户说：转给小王 500 元
  ↓ 输入守卫：归一化、注入特征
  ↓ 意图解析：落到 transfer，槽位 payee=小王 amountCents=50000
  ↓ 策略判定：黄，需确认
  ↓ 签发令牌：绑定会话、工具、参数摘要、有效期
  ↓ 执行：确认后扣账，写审计
  ↓ 渲染：数字全部来自工具返回
```

每段都有明确输入输出，接口写在 `docs/03` 的契约表里。

## 接口契约

两条路线的运行时都必须实现这五个接口，名称固定。

| 接口 | 输入 | 输出 |
|---|---|---|
| `chat(sessionId, text)` | 会话标识、用户原话 | 回复、判定、可选确认令牌 |
| `confirm(sessionId, token)` | 会话标识、令牌 | 执行结果或拒绝原因 |
| `cancel(sessionId)` | 会话标识 | 取消结果 |
| `state()` | 无 | 账户、卡片、订阅、持仓快照 |
| `audit(sessionId?, limit?)` | 可选会话、条数 | 审计记录与链校验结果 |

前端只认这五个。换路线不用改前端。

## 数据模型

金额一律整数分，不用浮点。这条不商量，浮点在金额上必然出错。

```ts
interface Account {
  holder: string
  balance: number      // 分
  available: number    // 分，扣掉预锁
}

interface Intent {
  scene: string        // 六个场景之一
  tool: string         // 工具名
  slots: Record<string, unknown>
  missing: string[]    // 缺的槽位，非空就追问
  confidence: number
}

interface Decision {
  level: "green" | "yellow" | "red"
  blocked: boolean
  requiresConfirm: boolean
  hits: Array<{ rule: string; detail: string }>
}
```

## 三条不可让的能力

无论选哪条路线，这三样必须在代码里，不能只在文档里。

**三色判定。** 判定要能解释：为什么黄，命中哪条规则。黑盒判定等于没有判定。

**注入防御。** 用户输入先归一化再匹配。全角、零宽、同形字都要处理。外部内容（账单备注、短信）只当数据，不当指令。

**审计留痕。** 每条决策一条记录，带前序哈希。评委要求现场改一条记录再校验，你必须能发现。

## 装配层差异

### Cordis

```ts
const ctx = new Context()
ctx.plugin(llmPlugin, { model: "deepseek-chat" })
ctx.plugin(toolsPlugin)
ctx.plugin(policyPlugin)
ctx.plugin(policyPlugin)   // 重复装载自动跳过
```

服务的依赖用 `inject` 声明，缺依赖时插件不启动并给出原因。清理动作用 `ctx.effect()` 注册，进程退出时自动执行。

### pi

```ts
const agent = new Agent({
  state: { messages: [], tools: [] },
  transport,                       // 管模型
  extensions: [toolsExt, policyExt],
  beforeTool: policyGuard,         // 钩子拦截
  afterTool: auditRecorder,        // 钩子记账
})
```

一轮对话由 Agent 驱动，钩子在工具调用前后插入。想加规则就加钩子，不改主循环。

## 扩展点

三条扩展路径，两条路线都支持。

| 要加什么 | 放哪 | 生效方式 |
|---|---|---|
| 新工具 | 运行时注册表 | 重启进程 |
| 新外部服务 | `mcp/servers.json` 加一条 | 重启进程，握手后自动注册 |
| 新技能 | `skills/` 放一个 Markdown | 下次请求自动进目录 |

技能的加载走两段式：系统提示词只放目录摘要，模型需要细节时再调 `skill_load` 取全文。这样新增技能不会撑爆提示词。

## 前端约定

前端只做三件事：发消息、看判定、点确认。

技术栈不限。包里给的是原生 TypeScript 加 Vite，没有框架依赖，改起来快。

页面必须显示三样：判定颜色、命中规则、审计编号。这三样是答辩时的证据。

## 目录映射

| 层 | Cordis 路线 | pi 路线 |
|---|---|---|
| 入口 | `web/`、`channels/` | 同左 |
| 编排 | `src/agent/loop.ts` | `src/agent.ts` |
| 装配 | `src/index.ts` 与 `src/plugins/` | `src/index.ts` 与 `src/extensions/` |
| 能力 | `src/services/` | `src/transport.ts` 与 `src/state.ts` |
