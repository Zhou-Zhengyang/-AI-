# 银行 AI 智能体 · 技术文档

> 2026 FinTechathon 微众银行金融科技大学生挑战赛

## 1. 项目概述

本项目是一个面向金融场景的 AI Banking Agent：用户用自然语言表达金融意图，系统完成意图理解、任务规划与受控执行。设计目标不是堆功能，而是三件事——判定可解释、操作有留痕、系统不乱动钱。

- 架构路线：pi 三段式（Agent + Transport + Extension），答辩口径为「钩子链 + 状态机」。
- 运行模式：规则优先、模型兜底。规则模式完全离线可跑；接入 DeepSeek（deepseek-v4-pro）后，模型处理规则覆盖不到的口语表达。
- 风险分级：三色判定——绿（只读 / 可逆低风险，直接执行）、黄（资金或状态变更，需确认）、红（不可逆或越权，直接拦截）。

## 2. 总体架构

```
用户输入（Web / Webhook）
        │
        ▼
归一化 + 注入检查（agent.ts）
        │
        ▼
规则解析 parseIntent（rules.ts）── 未命中 ──► 模型兜底 askModel（agent.ts）
        │
        ▼
三色判定 evaluate（rules.ts，五维度）
        │
   ┌────┼────┐
   红    黄    绿
 拦截  确认  执行
        │
        ▼
executeTool（state.ts）→ 审计入链（AuditChain）
```

三段职责：

| 段 | 文件 | 只负责 |
|---|---|---|
| Agent | track-pi/src/agent.ts | 状态、事件、循环、钩子调度、注入检查、确认流程 |
| Transport | track-pi/src/transport.ts | 模型请求、超时、离线回退 |
| Extension | shared/rules.ts + shared/state.ts | 意图、判定、令牌、审计、工具执行 |

## 3. 意图解析

位于 `shared/rules.ts`。

- `parseIntent`：按关键词路由，具体规则优先；规则判不出或置信度低于 0.7 才交给模型。
- `extractAmount`：先剔除手机号与长数字，再识别阿拉伯数字、中文数字、万 / 千、小数，以及独立 token 或句末的裸中文数字（「五百」「三千五」），统一返回整数分。
- `cnToNumber`：修正了「三千五 = 3005」的口语省略 bug，现正确返回 3500。
- `extractPayee`：手机号优先映射通讯录姓名，其次取语法位上的中文名。
- 多轮补槽：缺参数时写入草稿，追问后只补缺项；草稿合并逻辑已修复。
- 备注转账：命中「备注」直接拒绝，规则名 `remark-payee`，因为收款人来源不可信。

## 4. 三色判定

位于 `shared/rules.ts` 的 `evaluate`。五个维度叠加，任一判红即红，每条规则带独立规则名与含具体数字的说明：

| 维度 | 规则名 | 阈值 | 判红条件 |
|---|---|---|---|
| 操作类型 | base-level | — | 决定基线（只读绿 / 动账黄 / 改规则红） |
| 金额 · 单笔 | single-limit | 1000 元 | 单笔超限 |
| 金额 · 日累计 | daily-limit | 5000 元 | 今日已转 + 本次 超限 |
| 收款人 | new-payee | 500 元 | 收款人不在通讯录且金额达到阈值 |
| 可逆性 | irreversible | — | 挂失、赎回等不可逆操作 |
| 频次 | frequency | 5 笔/日 | 单工具当日执行次数达到上限 |

设计约束：

- 金额一律整数分，判定与执行不做浮点运算（显示用 `fenToYuan` 整数拆分）。
- 判定函数只读状态；日累计与频次通过 `dailyStats` 从审计链只读推导，判定不修改任何数据。
- 阈值集中在 `Policy` 配置（`track-pi/src/index.ts`），不散落在代码里。

## 5. 确认令牌与确认时重判

- `issueTicket` 绑定四样：会话标识、工具名、参数摘要（sha256）、过期时间（默认 120 秒）。
- `verifyTicket` 校验存在性、未过期、令牌匹配；令牌一次性，执行后立即失效。
- `confirm` 在执行前重新运行 `evaluate` 与 `beforeTool` 钩子，防止「判定通过后、确认前」状态变化导致带病执行（TOCTOU 防护）。

## 6. 审计链

位于 `shared/rules.ts` 的 `AuditChain`。

- 每条记录带前序哈希，sha256 成链；`verify` 全量校验，改一条即断裂。
- 记录携带结构化字段 `amountCents`、`payee`，供日累计与首次收款人判定只读推导。
- `redact` 在写入前脱敏手机号与 12–19 位长数字。

## 7. 模型兜底

位于 `track-pi/src/agent.ts` 的 `askModel`。

- `TOOL_SCHEMAS` 为每个工具声明真实参数契约（如 transfer 必填 `payee` 字符串 + `amountCents` 整数分），模型才知道如何填槽。
- 模型只产出意图，工具名经 `specOf` 白名单校验，金额经 `Number.isInteger` 且大于 0 校验，不合法即丢弃。
- 模型从不直接执行操作；执行权始终在代码层（`executeTool`），且必经判定与确认。
- `Transport` 用 `AbortController` 实现超时（`LLM_TIMEOUT_MS`，默认 20 秒），失败回退规则模式，不阻塞对话。

## 8. 场景与工具

| 场景 | 工具 | 基础判定 |
|---|---|---|
| 智能转账 | transfer | 黄 |
| 账单分析 | query_balance、analyze_bills | 绿 |
| 理财操作 | wealth_redeem | 红（不可逆） |
| 卡片管理 | lock_card、report_loss | 黄 / 红 |
| 订阅代扣 | list_subscriptions、cancel_subscription | 绿 / 黄 |
| 跨场景联动 | birthday_lock | 黄 |

## 9. 渠道与外部服务

- 渠道：Web 前端（`web/`）、通用 webhook（`channels/generic-webhook.mjs`）、企业微信适配（`channels/wecom.mjs`，需凭据，无凭据时 dryRun）。
- 外部服务：`mcp/` 提供汇率（fx）、反欺诈（risk）、理财费率（catalog）三个 stdio MCP 服务，`servers.json` 声明 `timeoutMs` 与 `risk`；运行时接入属下一步工作。

## 10. 接口

HTTP 单入口 `/rpc`（POST，body 为 `{ method, params }`）：

| method | params | 说明 |
|---|---|---|
| chat | [sessionId, text] | 一次对话 |
| confirm | [sessionId, token] | 确认待办 |
| cancel | [sessionId] | 取消待办 |
| state | [] | 账户快照 |
| audit | [sessionId?, limit?] | 审计记录与链校验 |
| health | [] | 健康检查 |

## 11. 运行

```powershell
# 规则模式（离线可跑）
node track-pi/src/index.ts

# 模型模式
$env:DEEPSEEK_API_KEY="你的密钥"
$env:LLM_MODEL="deepseek-v4-pro"
$env:LLM_THINKING="off"   # 抽槽走快路径
node track-pi/src/index.ts
```

默认监听 `http://127.0.0.1:18150`。

## 12. 测试与 CI/CD

- `node scripts/check.mjs`：结构完整性、密钥扫描、JSON 合法性（50/50 通过）。
- `node scripts/smoke.mjs`：冒烟用例 8 条，覆盖绿 / 黄 / 红、口语金额、越权、备注拒绝、注入。
- `track-pi` 内 `tsc --noEmit`：类型检查 0 错误。
- `web` 内 `vite build`：前端构建。
- `.github/workflows/ci.yml`：push / PR 自动跑 安装 → 自检 → 类型检查 → 前端构建 → 冒烟。
- `.github/workflows/release.yml`：打 `v*` 标签自动构建并发布 Release 产物。
