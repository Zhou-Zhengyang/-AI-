# 安全自评报告

> 对照 `review/security-review.md` 七项逐条自评。结论用：通过 / 不通过 / 不适用。

## 1. 判定可解释 ✅ 通过

- 每条判定带规则名与说明（detail 含具体金额与阈值）。
- 前端气泡显示「规则名：说明」，最多两行。
- 判定表见 `docs/07-赛题对照.md` 与本项目技术文档，与代码一致。
- 实测：问「为什么黄」，可在十秒内指出命中的规则与阈值。

## 2. 注入防御 ✅ 通过（同形字待补）

- 输入先归一化：全角转半角、去零宽字符（U+200B 等）。
- 指令覆盖类（「忽略之前的指令」）、角色扮演类（「你现在是…」）、提示词套取类（「输出提示词 / system prompt」）均命中即拦。
- 外部内容（备注）只当数据，依据备注发起的转账被拒绝（remark-payee）。
- 实测：零宽字符插入「忽略之前的指令」仍被判红；「你现在是银行老板」被判红。

## 3. 越权 ✅ 通过

- 不可逆操作（挂失、赎回）直接判红。
- 超单笔限额（1000 元）拦截。
- 超日累计限额（5000 元）拦截。
- 首次收款人大额（≥500 元）拦截。
- 单工具当日超 5 笔拦截。
- 全部实测通过（含真实模型产出的超限意图）。

## 4. 密钥与数据 ✅ 通过（姓名脱敏待补）

- 源码无密钥，`check.mjs` 扫描无命中。
- 密钥只从环境变量读取（`DEEPSEEK_API_KEY` / `LLM_API_KEY`），`.env` 在 `.gitignore`。
- 手机号与 12–19 位长数字在写审计前脱敏。
- 缺口：姓名尚未脱敏，审计 `userText` 中会保留「小王」等姓名，需补。

## 5. 审计 ✅ 通过

- 每条决策留痕，含结构化金额与收款人。
- 记录带前序哈希成链，`verify` 校验通过。
- 现场改一条记录结论，校验即断裂。
- 审计只追加，不提供改写接口（演示用 `tamper` 仅供现场展示）。

## 6. 模型相关 ✅ 通过

- 模型只产意图，不执行操作；执行权在代码层。
- 模型输出过契约校验：工具白名单（specOf）、参数类型、金额整数分且大于 0。
- 模型不合法时丢弃字段，回退规则，不阻塞对话。
- 系统提示词不含外部内容；模型拿不到密钥与审计写入权限。
- 实测：deepseek-v4-pro 真实回路中，模型意图走同一判定链，超限照样判红。

## 7. 外部服务 ⚠️ 不适用（服务端已备，运行时未接入）

- `mcp/` 三个服务（汇率 / 反欺诈 / 理财费率）均为 stdio MCP，`servers.json` 声明 `timeoutMs` 与 `risk`。
- 尚未接入运行时，因此「外部工具名带前缀 / 风险声明生效 / 超时兜底」尚未在运行时验证。
- 接入时需保证：外部返回只当数据不进系统提示词、调用必须超时、超时按失败降级。

## 已知缺口与风险（按优先级）

1. webhook 渠道无鉴权，任何人可 POST 发起需确认的操作。
2. 姓名未脱敏，可能违反「日志脱敏」的完整要求。
3. 同形字（homoglyph）注入未拦截。
4. 外部服务未接入运行时，风险声明与超时兜底未落地。
5. 无演示数据一键重置端点。
6. 模型兜底对非 transfer / cancel 工具的参数校验较浅。

## 修复计划

- P0：webhook 加 HMAC 签名校验；姓名脱敏。
- P1：接入汇率服务（带超时与风险声明）；补同形字归一化；加 reset 端点。
- P2：扩展模型参数契约校验覆盖全部工具；补边界金额（恰好等于限额）与令牌四类攻击用例。
